DéjàML · checks whether ML papers' results hold up

Same claim.
One more run.

DéjàML takes a machine-learning paper, finds its code, and runs the experiment again in a sealed, offline lab. The AI agents doing the work never see the result the paper reported. At the end you learn whether the number came back, with evidence for every step.

§01 the question

A paper says it got 0.906. Did it?

Checking one number from a paper is slow and error-prone. The code is often a notebook, not a script. Seeds go unset, file names don't match the public dataset, and library versions drift.

Worse, anyone who already knows the target may nudge the setup until it appears, often without meaning to.

DéjàML asks one narrow question. With this paper's exact code version, this dataset and this setup, what did we actually run, and how did the result compare?

paper
ROCKET: Exceptionally Fast and Accurate Time Series Classification Using Random Convolutional Kernels
what it is
ROCKET classifies time series. ECG200 is a small benchmark of 100 training and 100 test series.
claim
Page 25, Table 1, row ECG200: mean test accuracy 0.906 over 10 runs

§03 blinding target_sealed

Seal the number before anyone looks

Before any agent starts, DéjàML seals the paper's number away. It runs the number, its allowed margin of error and 32 random bytes through SHA-256, which produces a fingerprint that can't be reversed. Only the fingerprint stays in view, so no agent can steer the experiment toward the answer.

Sealed in your browser just now, with DéjàML's own algorithm
fingerprint
computing…
random bytes
32 random bytes

Why add random bytes? Without them, an agent could hash likely numbers like 0.906 until one matched the fingerprint. With them, the seal can't be guessed, even for a value as simple as 1.000.

From here on the agents work blind, and so does this page. The number is now blacked out at the top of the screen until §09.

§04 stages analyzing_paper ∥ analyzing_repository

Two analysts, working apart

PPaper Analyst · Reading Room

Reads the PDF and confirms the claim under test: page 25, Table 1, row ECG200. This claim was reviewed in advance. On a new paper, this agent picks the one result that an ordinary CPU-only run could re-check. It is the only agent that sees the paper's number before the reveal, 0.906, and that number is stripped from everything it hands on.

CRepository Analyst · Repo Room

At the same time, it clones angus924/rocket at commit 36bd908 and maps it: the script that runs the experiment (code/reproduce_experiments_ucr.py), the data, and where the result is written. It also flags that the repository doesn't list exact library versions.

The two can't see each other. Their findings meet only on a shared evidence board, in a fixed format.

§05 stages reconciling → policy_review

A plan, checked by code, not by a model

RReproduction Planner · Planning Room

Turns both reports into one exact plan, kept inside the environment, dataset and helper script reviewed for this claim: the command, Python 3.11, seven library packages at fixed versions, the dataset and its fingerprint, and the one field the result is read from (metrics.accuracyMean in artifacts/result.json).

The gate is plain code with fixed rules, so no AI decides whether its own plan is safe. Tick a box to break a rule.

§06 stage preparing

Every input, verified by hash

Python packages are fetched by short-lived helper containers that reach approved sites only through a filtering proxy. The dataset is downloaded only from an allowlisted site over HTTPS. Every file has to match its known fingerprint. The lab's system image is fixed by fingerprint too, and the lab never downloads anything itself.

§07 stage executing

The disposable lab

Code from a paper's repository could do anything, so it runs in a locked box. One to three Lab Engineers each get their own disposable Docker container with no internet, a read-only system, no admin rights, and hard limits of 2 CPUs, 4 GB of memory and 256 processes. The real settings:

docker create --network none --read-only \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 2 --memory 4096m --memory-swap 4096m \
  --pids-limit 256 --pull never --init \
  --tmpfs /tmp:rw,noexec,nosuid,nodev,uid=10001 …
# no network, read-only system, non-root user, every command time-capped (8 min for this run)

LLab Engineers · Disposable Lab

They run the approved command: 10 runs of ROCKET with 10,000 random kernels each. Then plain code reads the result from the file the run wrote, so no AI ever types the number. If a run breaks, a Debugger can be called in to read the logs.

§08 blinding observation_locked → blind_review_locked

Lock it, then judge it blind

First the measurement gets its own fingerprint, so it can't change once judging starts. Then an Independent Reviewer checks whether the run was faithful to the paper's method, still without knowing 0.906.

§09 blinding target_revealed → deterministic_comparison

Open the seal. Déjà vu?

Only now is the seal opened. DéjàML hashes the revealed number again, and it has to match the fingerprint from §03, or the study fails. That proves nobody changed the target along the way.

Recomputed in your browserThe seal opens when you reach this point in the study.

|0.904 − 0.906| = 0.002. The allowed margin, sealed before the run, was 0.0053. That's about how far two 10-run averages can drift apart by chance (a 95% allowance). So the result came back. The run needed DéjàML's own helper script, so the verdict is capped at Partially reproduced. DéjàML never claims more than its evidence supports.

All three came back within their margin. Each is capped at Partially reproduced because its run needed a declared change, a helper script or a compatibility fix.

Every possible verdict

  • Reproduced: official code, within tolerance, an equivalent protocol, no deviations.
  • Partially reproduced: the number matches, with declared deviations.
  • Not reproduced: a valid, equivalent run landed outside tolerance.
  • Inconclusive: the claim couldn't be measured in a way DéjàML can stand behind, for example missing data or no clear entry point.
  • Policy blocked: the plan broke a rule, such as asking for a GPU or an unknown download site.
  • Failed or cancelled: an infrastructure error or a user cancel. Labs are still destroyed.

§12 under the hood

Run it yourself

Seven AI agents, each with its own history, tools and budget, share findings only through the evidence board. A Node.js orchestrator moves the study from stage to stage and saves its place, so it can resume after a restart. The web app streams the study live into a 3D Research Campus. The campus on this page is modelled on it, with intake, policy-gate and prep stations added to show those stages.

# macOS or Linux: Node.js 24+, Python 3 and a running Docker engine
git clone https://github.com/AayushBhat07/dejaml.git
cd dejaml
npm run bootstrap

The bootstrap needs no model account. It builds and tests everything, then runs the real Urban Land Cover experiment offline in a non-root lab and checks its 79.88% result and cleanup receipt.
