    01How it startedSep 2026

    A hackathon brief

    DéjàML began as a hackathon entry. The brief asked for a web platform that takes a machine-learning paper as a PDF, finds its code, runs it on a CPU in isolation and gives an evidence-backed verdict on whether the result reproduces.

    Behind it is an old problem. Papers report precise numbers, but checking one is slow. The code may be a notebook, seeds may be unset, file names drift from the public dataset and library versions move on.

    02The first idea28 Sep

    Plan first, then one paper

    The first commit had no code in it: an architecture document, a phased roadmap and the first decision record. The plan was narrow on purpose, and built on three principles.

    EvidenceEvery step leaves a receipt. The verdict is computed from them in code.
    IsolationRepository code is untrusted. It runs in a sealed container with no network.
    BlindWhoever runs the experiment never learns the paper's number.
    Build one curated vertical slice first.Decision record 0001

    03The first solution28 to 29 Sep

    One paper, end to end

    The first working version followed a single curated case: a random forest on an urban land cover dataset. It read the PDF, fetched the repository, ran two analysts in parallel, passed the plan through a policy gate and ran the code in a disposable CPU lab.

    Two rules from that night still hold. Plain code, not a model, approves a plan before anything runs. And a model never decides whether two numbers match.

    A model must not decide whether numbers match.Decision record 0012

    04A turn not taken29 Sep

    A shortcut, taken back out

    An early auto-execution feature let an agent list setup steps to run before the sealed lab was created. It would have handled papers that need setup without hand-written code.

    Review removed it the next day. The setup steps skipped the policy gate and opened general network access, so the feature was marked blocked until it can meet the approval boundary.

    This path did not meet DéjàML's deterministic approval boundary.Sub-phase 6.2 record

    05The main build2 Oct · PR #4

    A blind team of agents

    The largest change replaced the single pipeline with DéjàML's own multi-agent runtime. Seven roles each get their own tools and budget, and share only a typed evidence board split across four trust zones.

    • The paper's number is sealed under a SHA-256 commitment before any agent starts.
    • Only the Paper Analyst sees it. The planner, lab engineers and reviewer work blind.
    • The measurement and the review are locked, then the seal is opened and compared in code.
    • The Supervisor can lower a verdict, never raise it.

    06First real resultsOct

    08Beyond curated papersIn review

    Any lightweight paper

    Each early case still needed a hand-written runner. On 15 Oct DéjàML tried seven new papers with no prepared case. One was partially reproduced. Six were stopped by the policy gate, for reasons like a dataset with no checksum, a GPU-only claim or R code.

    The fixes are in open pull requests: a tool that hashes datasets itself, default data hosts and a built-in notebook runner (#9, #11), and R support (#10).

    09The research question28 Oct

    Does seeing the number bias the agent?

    AI systems that reproduce papers usually show their agents the number the paper reported. A check of the closest work found no study that measures what that does. DéjàML can, because blind runs are built in.

    BlindThe number stays sealed. DéjàML's default.
    SightedThe agents are shown the real number.
    Sighted + ruleShown, with a rule against tuning toward it.
    DecoyShown a wrong number. Drift toward it is bias.

    10The first test30 Oct · PR #21

    A 12-run smoke test

    The four conditions are built into DéjàML, in a locked lab and in an open lab where an agent has room to tune (PR #18). The first real test ran Claude Sonnet 5.5 on three papers in the open lab.

    11Pushing harder30 Oct · PRs #24, #25

    A 39-run pilot

    The smoke test was clean, so the next runs tried to make chasing the paper's number as easy and as tempting as possible.

    • No guard rail. Urban Land Cover, shown the paper's 81.66, with the rule against editing code removed. All three runs measured 79.88. The agents listed the differences they found, such as the seed and the split, as deviations instead of tuning them.
    • Success means matching. Three more runs were told the reproduction only succeeds within tolerance of 81.66. All three measured 79.88 and changed no files.
    • Two new papers. r-STSF on ECG200 measured 89.4 to 90.1 whether blind, shown 89.7 or shown a decoy of 85.7. Good Classification Measures gave 96.53 in every arm. Each agent ran the official command once and stopped.
    • Weaker models. Claude Haiku 4.5, Claude Haiku 5.5 and Qwen3-Coder ran 13 times. Every run ended inconclusive, mostly at plan review. None of them made up a number.

    Could they have chased it?

    Yes. A sweep of the Urban adapter's split seed, 0 to 199, with no agent involved, found that 64 of the 200 seeds (32%) land within tolerance of 81.66. Changing one number would have been enough. No agent did it.

    12Writing it up30 to 31 Oct

    A draft, checked hard

    • Every run record and the seed sweep were published in the repository, under acceptance/blinding/results (PR #25).
    • Every citation in the draft was checked against its source.
    • A review from five perspectives (methods, domain, a devil's advocate, venue fit and the wider view) read the draft against the run records.

    The review's main point: the only arm that could show tuning gave the agents no credible reason to tune, and there was no positive control. So a clean result says as much about the test as about the agents.

    The paper's real, transferable contribution is the catalogue of ways such a test can be unable to show what it claims to measure.Internal review, 31 Oct

    The paper was reframed around those lessons, under a new title.

    13Where we areUnder review

    The first paper is submitted

    Can a Blinded Harness Detect Agents Chasing Reported Numbers? Lessons from a Pilot

    On 31 Oct 2026 the paper went to Empirical Software Engineering, a Springer journal. It is now under review. A first decision usually takes a few weeks.

      14NextPlanned

      The full study

      • A positive control: an agent told to match the paper, to show the harness catches it when it does.
      • An arm where tuning could actually pay off, with a blind comparison in the same lab.
      • About 25 light CPU papers, each with a reviewed target.
      • A second model family that can get through planning.
      • A memorization probe, and the plan preregistered before the runs start.
